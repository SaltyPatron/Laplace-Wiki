# Word sense disambiguation

A sense-annotated corpus attests which wordnet sense a token carries, and each dataset is its own witness because its identifiers start over.

## Format

| Record | Field | Order | Type | Specification |
| --- | --- | --- | --- | --- |
| `corpus` | `lang` | 1 | attribute, no type | Not defined by the README. `schema.xsd` declares `lang` with no type. Opened `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/schema.xsd` and `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README`. Opened `senseval2.data.xml`, `semcor.data.xml`, and `semcor+omsti.data.xml` have `lang="en"`. |
| `corpus` | `source` | 2 | attribute, no type | Not defined by the README. `schema.xsd` declares `source` with no type. Opened `senseval2` has `source="senseval2"`. Opened SemCor and SemCor+OMSTI both have `source="semcor"`. Opened ALL has `source="senseval2-senseval3-semeval2007-semeval2013-semeval2015"`. |
| `corpus` | additional attribute | any | `anyAttribute` | "Note that it is possible to add additional attributes if needed (e.g. fine-grained PoS tags)." `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README`. `schema.xsd` declares `xs:anyAttribute`. |
| `text` | `id` | 1 | attribute, required | Not defined by the README. The README names the tag order "corpus -> text -> sentence" and does not define `text` `id`. `schema.xsd` has `id` `use="required"`. Opened `id="d000"`. Opened ALL has `id="senseval2.d000"`. |
| `text` | additional attribute | any | `anyAttribute` | The same additional-attribute sentence. Opened SemCor and SemCor+OMSTI `text` has `source="br-e30"`, which the README does not define. `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `sentence` | `id` | 1 | attribute, required | Not defined by the README. `schema.xsd` has `id` `use="required"`. Opened `id="d000.s000"`. Opened ALL has `id="senseval2.d000.s000"`. |
| `sentence` | additional attribute | any | `anyAttribute` | "it is possible to add additional attributes if needed." `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `wf` | `lemma` | 1 | attribute, required | "Both types should contain two mandatory attributes ("lemma" and "pos")." `wf` is the "non-disambiguated" tag. `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `wf` | `pos` | 2 | `posType`, required | "The "pos" tag (Part-of-Speech), should follow the Universal PoS tags." [Universal POS tags](http://universaldependencies.org/u/pos/index.html). `schema.xsd` enumerates `ADJ`, `ADV`, `INTJ`, `NOUN`, `PROPN`, `VERB`, `ADP`, `AUX`, `CCONJ`, `DET`, `NUM`, `PART`, `PRON`, `SCONJ`, `PUNCT`, `SYM`, `X`, `.`, `CONJ`, and `PRT`. `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README`, `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/schema.xsd` |
| `wf` | text | 3 | `xs:string` | Not defined by the README. `schema.xsd` extends `xs:string`. Opened `wf` with `lemma="the"`, `pos="DET"`, and character data `The`. |
| `wf` | additional attribute | any | `anyAttribute` | "it is possible to add additional attributes if needed (e.g. fine-grained PoS tags)." `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `instance` | `id` | 1 | attribute, required | "instance" should additionally contain an id, which should be present in the gold file. `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README`. `schema.xsd` has `id` `use="required"`. Opened `id="d000.s000.t000"`. Opened ALL has `id="senseval2.d000.s000.t000"`. |
| `instance` | `lemma` | 2 | attribute, required | Mandatory attribute `lemma`. `instance` is the "disambiguated" tag. `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README`. Opened `lemma="art"` and `lemma="long"`. |
| `instance` | `pos` | 3 | `posType`, required | The same `pos` sentence and the same `posType` enumeration as `wf`. Opened `pos="NOUN"` and `pos="ADJ"`. |
| `instance` | text | 4 | `xs:string` | Not defined by the README. `schema.xsd` extends `xs:string`. Opened character data `art` and `long`. |
| `instance` | additional attribute | any | `anyAttribute` | "it is possible to add additional attributes if needed." `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `[dataset].gold.key.txt` line | instance id | 1 | text | "Each line is space-separated, where the first column corresponds to the instance id and the remaining columns correspond to the gold key/s." "The .txt gold file should contain all the disambiguation instances included in the XML." `/vault/Data/WSD/WSD_Evaluation_Framework/Data_Validation/README` |
| `[dataset].gold.key.txt` line | gold key | 2, one or more | WordNet 3.0 sense key | "the remaining columns correspond to the gold key/s." "All senses are annotated with WordNet 3.0." `/vault/Data/WSD/WSD_Evaluation_Framework/Evaluation_Datasets/README`, `/vault/Data/WSD/WSD_Evaluation_Framework/Training_Corpora/README`. Opened `d000.s000.t000 art%1:09:00::` and `d000.s000.t002 peculiar%5:00:00:specific:00 peculiar%5:00:00:characteristic:00`. The framework README does not define the key's components. |
| `sense_key` | `lemma` | 1 | lower case ASCII | "A sense_key is represented as lemma%lex_sense." "lemma is the ASCII text of the word or collocation as found in the WordNet database index file corresponding to pos. lemma is in lower case, and collocations are formed by joining individual words with an underscore (_) character." "A sense_key is the best way to represent a sense in semantic tagging." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5`. The framework README does not define this field. |
| `sense_key` | `%` | 2 | separator | "Concatenating the lemma and lex_sense fields of a sense index entry, using % as the concatenation character, creates the sense_key for that sense." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5` |
| `sense_key` | `ss_type` | 3 | one digit decimal | "ss_type is a one digit decimal integer representing the synset type." "1 NOUN, 2 VERB, 3 ADJECTIVE, 4 ADVERB, 5 ADJECTIVE SATELLITE." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5` |
| `sense_key` | `lex_filenum` | 4 | two digit decimal | "lex_filenum is a two digit decimal integer representing the name of the lexicographer file containing the synset for the sense. See lexnames(5WN)." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5` |
| `sense_key` | `lex_id` | 5 | two digit decimal | "lex_id is a two digit decimal integer that, when appended onto lemma, uniquely identifies a sense within a lexicographer file. lex_id numbers usually start with 00." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5`. On the data line, wndb's `lex_id` is one hexadecimal digit. |
| `sense_key` | `head_word` | 6 | lemma, or empty | "head_word is only present if the sense is in an adjective satellite synset. It is the lemma of the first word of the satellite's head synset." "For non-satellite senses the head_word and head_id fields have no values, however the field separator character (:) is present." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5`. Opened `art%1:09:00::` keeps both colons. Opened `peculiar%5:00:00:specific:00` has `head_word` `specific`. |
| `sense_key` | `head_id` | 7 | two digit decimal, or empty | "head_id is a two digit decimal integer that, when appended onto head_word, uniquely identifies the sense of head_word within a lexicographer file, as described for lex_id. There is a value in this field only if head_word is present." `/vault/Data/Wordnet/WordNet-3.0/doc/man/senseidx.5` |

| Field | Composition | Mask | What is recorded | Lineage or hop | Specification |

| gold key | The sense on the instance. The key is `lemma%ss_type:lex_filenum:lex_id:head_word:head_id`. [Claims](../Semantics/Claims.md#tuples) | Sense. [Claims](../Semantics/Claims.md#masks) | Which WordNet 3.0 sense the token carries. The gold key is the sense attestation. More than one key on a line is more than one sense of that instance. [Attestations](../Semantics/Attestations.md#attestations) | Each dataset is its own witness because its identifiers start over. Senseval 2, Senseval 3, SemEval 2007, SemEval 2013, SemEval 2015, SemCor, and SemCor+OMSTI each start at `d000.s000.t000`. Shared id strings between the evaluation files are not one instance: senseval2 and senseval3 share 867 id strings and 1 of those pairs has the same key. ALL is "The concatentation of the previous five evaluation datasets"; its ids are prefixed with the dataset name, so it is not a sixth witness. All 226036 SemCor keys occur in SemCor+OMSTI with the same key, so that overlap is lineage, not a second witness. The other 911134 SemCor+OMSTI keys are that dataset's own witness. The XML that is not the key is not a second sense witness.
