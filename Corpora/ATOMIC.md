# ATOMIC

ATOMIC 2020 and ATOMIC10X attest event-centered commonsense inference tuples (`[head, relation, tail]`), scoring ATOMIC10X candidates by `p_valid_model`, aliasing the `HinderdBy` schema typo onto `HinderedBy`, and treating tail `none` as explicit absence of an inference target rather than the English word `"none"`.

Two sources read the ATOMIC family, each under its own witness trunk and trust class:

- **ATOMIC 2020** (Hwang et al. 2021, [allenai.org/data/atomic-2020](https://allenai.org/data/atomic-2020)): human-curated social, physical, and event-centered commonsense tuples across 23 inference relations (`xIntent`, `xNeed`, `xAttr`, `xEffect`, `xWant`, `xReact`, `oEffect`, `oWant`, `oReact`, `AtLocation`, `ObjectUse`, `HasSubEvent`, `HinderedBy`, `isAfter`, `isBefore`, `Causes`, `xReason`, ...).
- **ATOMIC10X** (West et al. 2022): symbolic commonsense distillation generated by a language model and filtered/scored by a learned critic (`p_valid_model`), admitted at `class AIModelProbe`.

## ATOMIC 2020 (`train.tsv`, `dev.tsv`, `test.tsv`)

Each tab-separated line holds `head`, `relation`, and `tail`.

> [!IMPORTANT]
> **Explicit `none` absence marker in `tail`:** In ATOMIC (`Sap et al. 2019` / `Hwang et al. 2021`), annotators write `none` in `tail` when an event has **no** applicable inference under that relation (for example, `PersonX sneezes` → `xIntent` → `none`, meaning unintentional). Recording literal `none` as an ordinary tail text falsely collides every absent consequence or absent intent onto the English word `"none"`! Under the Recording Law, `tail == "none"` represents an explicit null/absent-target marker for `[head, relation]` (either attested as explicit non-applicability of `relation` on `head` or omitted from target-entity tuples—never linked to the English lexical item `"none"`; `Batch 2` recipe fix for `atomic-2020/tuples.recipe` and `atomic-10x/tuples.recipe`).

| Piece | Written as | Laplace reads it as | Target attestation & current recipe state | Specification |
| --- | --- | --- | --- | --- |
| column 1 (`head`) | `"PersonX pays PersonY a compliment"` | event/entity subject | first part of `[head, relation, tail]` | "column 1: head node/concept" |
| column 2 (`relation`) | `xWant`, `xAttr`, `HinderedBy`, `AtLocation`, ... | ATOMIC relation inventory (`value - relation`) | predicate of `[head, relation, tail]` | "column 2: edge relation" |
| column 3 (`tail` != `none`) | `"to be nice"` | inferred event, mental state, attribute, or object | `[head, xWant, tail]` | "column 3: tail node/concept" |
| `none` in column 3 | `none` | explicit schema absence marker ("no applicable target for `relation` on `head`"), **never** the English word `"none"` | target: explicit absence / non-applicability marker or empty target (`Batch 2` gap: `atomic-2020/tuples.recipe` currently lacks `when tail is none` handling and records literal `none`) | ATOMIC annotation convention for absent mental-state/effect dimension |
| empty field | | attests nothing | none | |

## ATOMIC10X (`ATOMIC10X.jsonl`)

Each JSON line holds `head`, `relation`, `tail`, `p_valid_model`, `split`, and recall-cutoff booleans `rec_0.5..rec_0.9`.

- **Critic probability scoring (`p_valid_model`)**: `atomic-10x/tuples.recipe` scores every tuple directly by `p_valid_model` in `[0, 1]` (`score record p_valid_model`, `omit split rec_* p_valid_model`), so high-confidence critic predictions (`0.98`) win within `AIModelProbe`'s trust ceiling while low-confidence hallucinations (`0.12`) score as losses.
- **Canonicalizing `HinderdBy` → `HinderedBy`**: ATOMIC10X's publisher schema misspells ATOMIC 2020's `HinderedBy` relation as `HinderdBy`. Under the Recording Law (`INVENTOR_RECORD.md:285`), curated recipe vocabulary mapping aliases `HinderdBy` → `HinderedBy` so identical tuples across `ATOMIC 2020` and `ATOMIC10X` collide on the **exact same `[head, HinderedBy, tail]` claim cell** in `consensus` (`Batch 2` recipe fix in `atomic-10x/tuples.recipe`).

| Piece | Written as | Laplace reads it as | Target attestation & current recipe state | Specification |
| --- | --- | --- | --- | --- |
| `head` | string | event subject | first part of `[head, relation, tail]` | "`head` is the event for this example" |
| `relation` | `xNeed`, `xReact`, `xEffect`, `xIntent`, `xAttr`, `xWant`, `HinderdBy` | ATOMIC relation, with publisher typo `HinderdBy` aliased to `HinderedBy` | `[head, HinderedBy, tail]` (`Batch 2` gap: `atomic-10x/tuples.recipe` awaits `HinderdBy` → `HinderedBy` alias) | 7-relation symbolic distillation inventory |
| `tail` | string (excluding `none`) | inferred target (with `none` handled as explicit absence as in ATOMIC 2020) | `[head, relation, tail]` | "`tail` is the inference for this example" |
| `p_valid_model` | float in `[0, 1]` | attestation outcome score (`score record p_valid_model`) | scored outcome (`0` loss .. `1` win, already active in `atomic-10x/tuples.recipe`) | "the score assigned by the critic model" |
| `split`, `rec_0.5..rec_0.9` | string, booleans | dataset split and redundant threshold flags (`omit split rec_*`) | none (`p_valid_model` carries the exact continuous score) | recall-threshold indicators derived from `p_valid_model` |

## Relations

ATOMIC's relation tokens (`xWant`, `xIntent`, `xNeed`, `xEffect`, `xReact`, `xAttr`, `HinderedBy`, `AtLocation`, ...) are already semantic inference relations rather than column headers. Closing the two `Batch 2` recipe items—aliasing `HinderdBy` → `HinderedBy` and guarding `tail == "none"`—ensures clean cross-witness convergence with `ATOMIC 2020` and prevents `"none"` hub pollution.
