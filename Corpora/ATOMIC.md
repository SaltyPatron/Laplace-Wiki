# ATOMIC

ATOMIC 2020 attests each of its tuples as the claim of a head, a relation, and a tail, and ATOMIC10X attests tuples of the same shape as an unrated witness, each scored by its critic's `p_valid_model`, with its other members said of the tuple itself; a tail written `none` is recorded as written and stands for nothing the set explains.

Two sources read ATOMIC, each its own witness. ATOMIC 2020 is the knowledge graph of Hwang et al. 2021, at [allenai.org/data/atomic-2020](https://allenai.org/data/atomic-2020): commonsense tuples, a head, a relation, and a tail on every line, in three tab-separated files. ATOMIC10X is the set of West et al. 2021: a JSON object on every line, each a head, a relation, and a tail with what the set says of that tuple. Neither is a copy of the other, and neither is the other's lineage.

## ATOMIC 2020

A record is one line of `train.tsv`, `dev.tsv`, or `test.tsv`. The README says of the tables: "All data `*.tsv` files are formatted as follows: each line represents a distinct commonsense tuple; column 1: head node/concept; column 2: edge relation (e.g., xWant,xAttr,AtLocation); column 3: tail node/concept". The tables have no header row. The recipe tells the columns apart by the README's words for them, `head`, `relation`, `tail`; the words only say which column is which and are never recorded.

| Piece | Written as | Laplace reads it as | Claim recorded | Specification |
| --- | --- | --- | --- | --- |
| column 1 | the head | the subject | the first part of the claim | "column 1: head node/concept" |
| column 2 | `xWant`, `xAttr`, `AtLocation`, ... | the predicate | the second part | "column 2: edge relation (e.g., xWant,xAttr,AtLocation)" |
| column 3 | the tail | the object | `[head, xWant, tail]` | "column 3: tail node/concept" |
| `none` in column 3 | `none` | recorded as written: the README does not say what it stands for | `[head, relation, none]` | |
| an empty field | | nothing | none | |
| `README.md`, and any other `*.md` or `*.txt` under the root | not read | no recipe matches them and the source has no `reads` line | none | |

Every row is recorded in its own order, as written, and a row is one claim, witnessed once by `ATOMIC 2020 Knowledge Graph`. The split a row is in is not recorded: `train.tsv`, `dev.tsv`, and `test.tsv` are read the same way.

## ATOMIC10X

A record is one line: one JSON object. Its members `head`, `relation`, and `tail` are the tuple, in that order; every other member is said of the tuple itself, under its own name. The set has no README on this machine; what is quoted below is the release's field list.

| Piece | Written as | Laplace reads it as | Claim recorded | Specification |
| --- | --- | --- | --- | --- |
| `head` | a text | the subject | the first part of the claim | "head is the event for this example (string)" |
| `relation` | `xNeed`, `xReact`, `xEffect`, `xIntent`, `xAttr`, `xWant`, `HinderdBy` | the predicate, as written; the field list spells `HinderdBy` | the second part | "the relation for this example, one of [xNeed, xReact, xEffect, xIntent, xAttr, xWant, HinderdBy]" |
| `tail` | a text | the object | `[head, xAttr, tail]` | "tail is the inference for this example (string)" |
| `p_valid_model` | a number between 0 and 1 | the score the tuple is attested with, on the scale the set writes it on: 0 a loss, 1 a win, halfway a draw (`score record p_valid_model`); not said of the tuple | the row's outcome | "the score assigned by the critic model (float)" |
| `split` | `train`, `test`, `val` | which part of the release a line is in: not read (`omit split`) | none | "the dataset split for this example, one of [train, test, val]" |
| `rec_0.5`, `rec_0.6`, `rec_0.7`, `rec_0.8`, `rec_0.9` | `true` or `false` | `p_valid_model` against a threshold, each true where it is at least 0.65344, 0.83781, 0.92709, 0.95577, 0.96755 (checked on 1M lines): not read (`omit rec_*`); the tuple is scored by `p_valid_model` itself | none | "rec_X is whether this example is cutoff by the critic at an expected recall of X. High filtration uses 0.5"; "Medium filtration uses 0.8" |
| `null`, an empty text | | nothing | none | |

Everything one line says it says together: the tuple and what is said of it are one record, witnessed once by `ATOMIC10X`, and the tuple within it plays at the score `p_valid_model` gives. A tuple ATOMIC 2020 also states is the same claim, said by two witnesses of their own.

## Relations

As built, the relation of every claim above is ATOMIC's relation, `xAttr`, `xWant`, `HinderdBy`, as each tuple writes it: markup, not meaning. A relation is what the source means, never the name of a field, column, attribute, or layer, [10. Recipes](../Sequence/Recipes.md#1011-disposition-every-recovered-field). The target for each column is what the source documents it to mean, quoted in the Specification column; a column whose meaning the source does not document is an explicit unresolved obligation, its target the meaning the source documents. Those relations are already meaning, values of ATOMIC's relation inventory, and none of them is a field's name; `none` in the tail is recorded as written because the README does not say what it stands for.
