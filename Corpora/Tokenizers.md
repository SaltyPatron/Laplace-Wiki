## Format

| Record | Fields in order | What a record is | Proof |
| --- | --- | --- | --- |
| BertTokenizer vocabulary | vocab_file, one vocabulary file | The BertTokenizer page says the vocab_file is the file containing the vocabulary, and that the tokenizer is based on WordPiece. | [BERT, BertTokenizer](https://huggingface.co/docs/transformers/model_doc/bert) |
| GPT2Tokenizer files | vocab_file, merges_file | The GPT2Tokenizer page says those are the path to the vocabulary file and the path to the merges file, and that the tokenizer is based on byte-level Byte-Pair-Encoding. | [GPT-2, GPT2Tokenizer](https://huggingface.co/docs/transformers/model_doc/gpt2) |
| CodeGenTokenizer files | vocab_file, merges_file | The CodeGenTokenizer page says the vocabulary is loaded from vocab_file and the merges are loaded from merges_file, and that the tokenizer is based on byte-level Byte-Pair-Encoding. | [CodeGen, CodeGenTokenizer](https://huggingface.co/docs/transformers/model_doc/codegen) |
| LlamaTokenizer files | vocab, merges | The LlamaTokenizer page says vocab is a path to the vocabulary file, a dictionary, or a list of tokens, and merges is a path to the merges file or a list of merges. | [Llama, LlamaTokenizer](https://huggingface.co/docs/transformers/model_doc/llama) |
| Qwen2Tokenizer files | vocab.json, merges.txt, tokenizer.json | tokenization_qwen2.py names those three files. It does not state an order of fields inside them. | [tokenization_qwen2.py at v5.17.0](https://github.com/huggingface/transformers/blob/v5.17.0/src/transformers/models/qwen2/tokenization_qwen2.py) |
