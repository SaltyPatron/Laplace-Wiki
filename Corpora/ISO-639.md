# ISO 639

ISO 639 attests what each list says of a language code, under the list's own field names, and nothing renames or reconciles the codes across the lists.

One source directory reads the language identifiers: the Library of Congress's ISO 639-2 list and its RDF of ISO 639-1, 639-2 and 639-5, SIL's ISO 639-3 tables, the IANA language subtag registry, and CLDR's supplemental data. Every recipe names its own witness, so the source's own witness, `ISO 639`, is the one no recipe uses. A code is recorded as each list writes it, and no recipe names a lineage: a list that repeats another's code says so on its own.

## The ISO 639-2 list

`ISO-639-2_utf-8.txt` is a table of five fields parted by `|`, with no header row, read by [`iso-639-2.recipe`](https://github.com/SaltyPatron/Laplace-Engine/blob/main/recipes/iso-639/iso-639-2.recipe). The file names none of its fields and no documentation of them is kept with it, so no field is given a name: each row says its first field and each of its other fields side by side, as a pair, in the row's own order. The numbers below say where a field stands in the row; they are not recorded. The file does not name who publishes it; the recipe names the Library of Congress, whose RDF of the same list is read below.

| Piece | Laplace reads it as | Claim recorded | Specification |
| --- | --- | --- | --- |
| field 1 | the subject of every pair of the row | the first part of each pair | "An alpha-3 (bibliographic) code, an alpha-3 (terminologic) code (when given), an alpha-2 code (when given), an English name, and a French name of a language are all separated by pipe (\|) characters." [Code list for downloading](https://www.loc.gov/standards/iso639-2/ascii_8bits.html) |
| field 2 | the pair of it and field 1, as written | `[field 1, field 2]` | "an alpha-3 (terminologic) code (when given)". "One set is for bibliographic applications, often referred to as ISO 639-2/B, and the other for terminology applications, referred to as ISO 639-2/T." [ISO 639-2 FAQ](https://www.loc.gov/standards/iso639-2/faq.html) |
| field 3 | the pair of it and field 1 | `[field 1, field 3]` | "an alpha-2 code (when given)" [Code list for downloading](https://www.loc.gov/standards/iso639-2/ascii_8bits.html) |
| field 4 | the pair of it and field 1 | `[field 1, field 4]` | "an English name"; the code list's column is "English name of Language" [ISO 639-2 code list](https://www.loc.gov/standards/iso639-2/php/code_list.php) |
| field 5 | the pair of it and field 1 | `[field 1, field 5]` | "a French name of a language"; the code list's column is "French name of Language" [ISO 639-2 code list](https://www.loc.gov/standards/iso639-2/php/code_list.php) |
| an empty field | what the list leaves empty | nothing | "If one of these elements is not applicable to the entry, the field is left empty" [Code list for downloading](https://www.loc.gov/standards/iso639-2/ascii_8bits.html) |

Each pair is a claim of its own. The code list's German name is not in this file and is not read from it.

## The Library of Congress RDF

`iso639-1.rdf`, `iso639-2.rdf` and `iso639-5.rdf` are the Library of Congress's lists of ISO 639-1, 639-2 and 639-5 in RDF/XML, "the fullest of the four formats it publishes them in", read by [`loc.recipe`](https://github.com/SaltyPatron/Laplace-Engine/blob/main/recipes/iso-639/loc.recipe) as a query over the XML. Every statement is recorded as written: the subject is what `rdf:about` names, the predicate the property element's own name, the object its text, or what its `rdf:resource` names, or what the `rdf:about` of the element inside it names. The witness is `Library of Congress`. A recipe with a query is a curated source: what is recorded is what it attests, never the file's own syntax.

| Piece | Written as | Laplace reads it as | Claim recorded | Specification |
| --- | --- | --- | --- | --- |
| `rdf:about` | the first attribute of an element | the resource the statements are of; the patterns name it by position, because these files write it first wherever they write it | the subject | the ISO 639 vocabularies of [id.loc.gov](https://id.loc.gov/vocabulary/) |
| a property element with text, such as `madsrdf:code` | `<madsrdf:code>en</madsrdf:code>` inside the resource's element | said of the resource under the element's own name, the text as written | `[resource, madsrdf:code, code]` | "ISO 639-1 provides two-character lowercase alphabetic strings that serve as identifiers of languages." The `rdfs:comment` of the 639-1 scheme; "ISO 639-5 provides three-character lowercase alphabetic strings that serve as identifiers for the representation of names of living and extinct language families and language groups." The `rdfs:comment` of the 639-5 scheme |
| a text that carries an attribute | `<madsrdf:authoritativeLabel xml:lang="en">...` | the text says so: the attribute said of the text under the attribute's name; `xmlns` attributes are not read | `[text, xml:lang, en]`; the 639-2 list writes its German names with `lclang="de"`, recorded as `[text, lclang, de]` | the code list's columns are "English name of Language", "French name of Language", "German name of Language" [ISO 639-2 code list](https://www.loc.gov/standards/iso639-2/php/code_list.php) |
| an empty property element with `rdf:resource` | `<element rdf:resource="..."/>` | said of the resource under the element's name; the object is what `rdf:resource` names | `[resource, element, what rdf:resource names]` | |
| a property element holding an element with its own `rdf:about` | `<element><inner rdf:about="..."/></element>` | said of the resource under the outer element's name; the object is what the inner `rdf:about` names | `[resource, element, inner resource]` | |
| a property element with `rdf:parseType="Literal"` | markup as its value | said of the resource under the element's name; the object is the content node itself, as recorded, markup and all | `[resource, element, content]` | |
| the element that carries `rdf:about` | `<element rdf:about="...">`, any element but `rdf:Description` | the element says its own name of what it names: the file writes nothing between the two | `[resource, element name]` | |
| `rdf:Description` carrying `rdf:about` | | not read as a pair: it names nothing of its own | nothing | |
| a property element whose text holds `<` | | not read as text: what is inside it is read on its own | nothing | |

Each claim stands alone. The 639-5 RDF carries the identifiers and names; the `639-2`, Hierarchy and Notes columns of the [ISO 639-5 identifier list](https://www.loc.gov/standards/iso639-5/id.php) are not in it, and are not read.

## The ISO 639-3 tables

The tables do not name who publishes them; the pages kept beside them are signed "Copyright © 2026 SIL Global", and the witness is `SIL Global`. ## The IANA registry

`language-subtag-registry.txt` is the IANA language subtag registry: records of `Key: Value` lines parted by `%%`, read by [`iana.recipe`](https://github.com/SaltyPatron/Laplace-Engine/blob/main/recipes/iso-639/iana.recipe). Every field is said of the record's subtag or tag, under the field's own name. The file does not name who publishes it; the witness is `iana`, the name of the directory it is kept in.

| Piece | Written as | Laplace reads it as | Claim recorded | Specification |
| --- | --- | --- | --- | --- |
| `Subtag`, or `Tag` when the record has no `Subtag` | `Subtag: value` | what the record is about | the subject | "Subtag", "Tag" [RFC 5646, 3.1.4](https://www.rfc-editor.org/rfc/rfc5646) |
| every other field: `Type`, `Description`, `Added`, `Deprecated`, `Preferred-Value`, `Prefix`, `Suppress-Script`, `Macrolanguage`, `Scope`, `Comments` | `Key: Value`; a line that begins with a space continues the field before it, joined with a space | said of the subtag under the field's own key; a field written twice, such as two `Description` lines, is two claims | `[subtag, Type, value]`, `[subtag, Description, text]` | the record fields of [RFC 5646, 3.1.2](https://www.rfc-editor.org/rfc/rfc5646); the registry at [IANA](https://www.iana.org/assignments/language-subtag-registry) |
| `%%` | a line of its own | what parts one record from the next | nothing | "%%" [RFC 5646, 3.1.1](https://www.rfc-editor.org/rfc/rfc5646) |
| `File-Date` | the first record | a record with neither `Subtag` nor `Tag`: nothing to say it of | nothing | "File-Date" [RFC 5646, 3.1.1](https://www.rfc-editor.org/rfc/rfc5646) |

Each claim stands alone.

## CLDR

Four recipes read the Unicode CLDR files kept with the identifiers, each as XML read as what it says: the recipe names which elements are things and what names each, and every other attribute of a thing is said of it under the attribute's own name. The witness is `CLDR`. Each file says "CLDR data files are interpreted according to the LDML specification", [UTS #35](https://www.unicode.org/reports/tr35/), under the notice "Copyright © 1991-2015 Unicode, Inc." or "Copyright © 1991-2026 Unicode, Inc."

What one element says it says together, as one record: a thing's own attributes, its own text, and its place in the thing it is inside; an element that is not a thing speaks of the thing it is inside, and is one record of its own. An element inside no thing, such as a file's root or its `version`, speaks of nothing. An empty attribute value attests nothing.
