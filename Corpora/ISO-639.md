# ISO 639

ISO 639 is each authority's own corpus, the Library of Congress, SIL, IANA, CLDR, and Glottolog, each attesting what its list says of a language code, as built under the list's own field names; the 2↔3-letter links and the macrolanguage relations are relations those corpora attest, and nothing renames or reconciles the codes across the lists.

Each language-code registry is an authoritative reference corpus: the Library of Congress's ISO 639-2 pipe list and RDF/XML releases of ISO 639-1, 639-2, and 639-5; SIL Global's ISO 639-3 code, name-index, macrolanguage, and retirement tables; the IANA BCP 47 language subtag registry; Unicode's CLDR supplemental data (`likelySubtags`, `languageAlias`, BCP 47 extensions); and Glottolog's languoid genealogy and Glottocode crosswalks. The 2↔3-letter equivalences (`en` ↔ `eng`), bibliographic/terminologic pairs (`fre` ↔ `fra`), and macrolanguage memberships (`zho` → `cmn`, `yue`) emerge directly as attested highway relations across those authorities without ad-hoc code rewriting.

## The Library of Congress RDF & Atom feed (`loc.recipe`, `loc-feed.recipe`)

`iso639-1.rdf`, `iso639-2.rdf`, and `iso639-5.rdf` are RDF/XML vocabularies from [id.loc.gov](https://id.loc.gov/vocabulary/), read by [`loc.recipe`](https://github.com/SaltyPatron/Laplace-Engine/blob/main/recipes/iso-639/loc.recipe) (with `iso639-5.atom10.xml` read by [`loc-feed.recipe`](https://github.com/SaltyPatron/Laplace-Engine/blob/main/recipes/iso-639/loc-feed.recipe)). `rdf:about` identifies each language or language-family resource; `madsrdf:code`, `madsrdf:authoritativeLabel` (including English, French, and `lclang="de"` German labels), and `rdf:resource` cross-links are attested of that resource (`Batch 2` extends ISO 639-5 coverage where tabular `Hierarchy` parent-family links supplement `iso639-5.rdf`).

## The IANA language subtag registry (`iana.recipe`)

`language-subtag-registry.txt` ([RFC 5646](https://www.rfc-editor.org/rfc/rfc5646), [IANA](https://www.iana.org/assignments/language-subtag-registry)) consists of `%%`-delimited `Key: Value` blocks (with leading-space folded continuation lines). Each `Subtag` or `Tag` attests its `Type` (`language`, `extlang`, `script`, `region`, `variant`, `grandfathered`, `redundant`), `Description` names, `Suppress-Script`, `Macrolanguage`, `Preferred-Value`, `Prefix`, `Scope`, and `Comments`, while the header `File-Date` and per-entry `Added` dates are registry bookkeeping.

## Unicode CLDR supplemental tables (`cldr-*.recipe`)

Four XML recipes read Unicode CLDR's BCP 47 extension keys/types (`cldr-bcp47.recipe`), `likelySubtags.xml` (`cldr-likely-subtags.recipe`, e.g., `zh` → `zh_Hans_CN`, `und_Latn` → `en_Latn_US`), `supplementalData.xml` (`cldr-supplemental-data.recipe`: territory language populations, scripts, currencies, calendars, parent locales), and `supplementalMetadata.xml` (`cldr-supplemental-metadata.recipe`: `languageAlias`, `scriptAlias`, `territoryAlias` replacements and reasons) under [UTS #35](https://www.unicode.org/reports/tr35/).

## Glottolog (`Batch 2` recipe queue)

Glottolog ([glottolog.org](https://glottolog.org/)) supplies fine-grained languoid genealogies (families, subfamilies, languages, and dialects identified by 8-character Glottocodes such as `stan1293`), geographic coordinates, macroareas, endangerment status, and Glottocode ↔ ISO 639-3 crosswalks. A declarative `.recipe` for Glottolog's CLDF/CSV languoid tables is queued for `Batch 2` so low-resource languages and dialects without an ISO 639-3 code join the language highway cleanly alongside `SIL Global` and `CLDR`.

## Relations

In target form, every authority's field headers (`Part1`, `M_Id`, `Preferred-Value`, `replacement`, `likelySubtag`) resolve to their RFC 5646, ISO 639, UTS #35, and Glottolog semantic relations (code equivalence, macrolanguage membership, script suppression, likely-subtag expansion, genealogical parent), with each authority standing on its own source trunk.
