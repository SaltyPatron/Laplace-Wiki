2. WORKING INTERPRETATION -- STILL TO VALIDATE WITH THE USER

- Recursive containment supplies the constituent DAG. Identifier references and
  witnessed relations provide additional routes through that knowledge graph.
- Distinguish reconstructing an entity's own content from expressing something
  about it in a requested language/context. Both must operate over the substrate.
  This distinction must not become a second, disconnected label system.
- Example to validate: reconstructing the content of an ILI identifier can yield
  its identifier string; expressing what it denotes in English follows witnessed
  lexical connections and renders the resulting content.
- A BLAKE3 ID addresses content; the original bytes are recovered through the
  retained structure/perf-cache and admitted realization rules, not by reversing
  the hash. Identifier content, source record content, and claims connecting them
  must retain their respective identities.
- A registry miss alone does not establish that lawful content cannot render.
  Missing required structure, absent naming testimony, and a failed operation
  need distinct outcomes. Substituting a generic label does not repair traversal.
- These are interpretations for discussion, not additional user-approved laws.
- Proposed operational consequence to examine: each higher operation has
  constituent operations, required inputs, and a completion/result contract.
  Dependencies determine sequencing; independent branches may run concurrently.
  A consumer must not assume a prerequisite result was established elsewhere.
  This does not yet assert that the current failures share one causal defect.

Observed implementation bands (descriptive, NOT approved logical tier numbers)

Machine execution and numerical contract:
  - C17, fixed-width C ABI types, platform calling convention, memory operations,
    scalar arithmetic/bit operations, and CPU-specific intrinsic implementations.
  - Native/src/cpu.c detects CPU/OS state, selects kernels once, and permits an
    ISA cap. Actual kernels include scalar, AVX2, AVX-512 and separate VNNI paths.
  - Native/cmake/LaplaceFlags.cmake imports Operations/toolchain/flags.cmake for
    the floating-point contract. CMake links pinned BLAKE3 and CORE-MATH.
  - These are physical implementations of an operation. A different instruction
    sequence must not silently redefine its semantic inputs, outputs, or identity.

Canonical values and representations:
  - Native/include/laplace/laplace.h defines lp_id (16 bytes), lp_coord (four
    fixed-point axes at 2^53), lp_ref, path/vertex representations and buffers.
  - Native/src/identity.c implements codepoint and ordered-child composition IDs.
    Mono engine/core/src/hash128.c delegates multi-child hashing to lp_id_compose.
  - Native/src/text.c uses ICU break iterators; its comments explicitly declare
    word-rule tailoring and repetition factoring. Calling it UAX #29 alone does
    not specify that complete decomposition contract or establish mono parity.
  - Unicode/UTF-8/UAX #29, BLAKE3, correctly rounded math, and EWKB are external
    building blocks. Laplace's composition, packed metadata, traversal meanings,
    scopes, unknown states, and operation-composition rules remain its own laws.

Local structural and computational primitives:
  - Native/src/path.c: decode ID/run metadata, expand ordered constituents,
    collect distinct keys, test containment, count occurrences, match ordered
    continuation, and identify a tuple's opposite endpoint.
  - Native/src/compose.c: compose child IDs and coordinate accumulations.
  - Native/src/pull.c: lp_frontier_reach/next, ID-keyed reached state plus heap,
    cost/estimate ordering and visited/closed state. Engine program.c uses this
    shared frontier in its SCAN implementation.
  - Other native families include real-coordinate geometry and consensus math.
    Presence of these families does not prove their higher callers compose them
    correctly, preserve provenance, or execute within the declared work envelope.

Indexed access and traversal:
  - Modular postgres/src/laplace_pg.c provides set-oriented paths, containers,
    claims, occurrences, continuation and coupling entry points over native
    primitives. Engine/src/read.c fetches requested path sets and decodes them
    through lp_path_*; walk.c composes upward/downward provenance walks.
  - Mono SQL function families include structural.*, consensus.*, realize.* and
    ops.*; their native implementations use prepared SPI and the SQL catalog.
    They are not automatically interchangeable with the modular encodings.

Contracts being made concrete

A. Identity is exactly 16 bytes, throughout the native read boundary.
   The shared datum_to_hash128 decoder previously rejected short bytea values
   but silently accepted a longer value by copying its first 16 bytes. It now
   rejects both lengths with PostgreSQL invalid_parameter_value (22023).
   This prevents an oversized request from impersonating a valid prefix identity.

B. Availability includes the existing native Unicode floor.
   A missing laplace.entities row does not make a cache-resident atom absent.
   Native read_facets now reconciles stored rows with the existing native
   codepoint reverse index; recognized atoms have tier 0 and Codepoint type.
   ops.entity_facets_batch is the native implementation; scalar entity_facets
   delegates to that batch. The catalog's entity.facets delegates to the same
   operation, so C#, nested display reads, and direct SQL share that rule.
   Unknown identities still produce no facet row. Duplicate requests produce
   one facet row per identity; display preserves original positions/duplicates.

C. Structural type and attested semantic type are different projections.
   Display still reads the stored structural type to decide how content renders.
   Facets retain the ranked IS_TYPED_AS family override over the stored type.
   The stored-row catalog query now uses the same relation-family rule as the
   existing public facet function. A source binding must not cause textual
   content to stop being rendered as its own surface.

D. Registry lookup, realization, lexicalization, and display have distinct jobs.
   lexical.type_label is an immutable governed-registry lookup. It is allowed
   to return NULL for source-defined relation content; its meaning was preserved.
   Outgoing and incoming labeled consensus now pass distinct relation and
   endpoint IDs through the shared native display pipeline in one bounded batch.
   Repeated relation IDs do not multiply the result set. High-tier content keeps
   the renderer's bounded preview rules. An unavailable surface retains a short
   ID in display, with the full identity separately present in the result.
   That identity-bearing display fallback is not a claim of exact reconstruction.

E. Every composed read must preserve its prerequisites and failure disposition.
   The two C# consensus readers now bind catalog-owned statements instead of
   private SQL. Incoming inspection no longer discards cache-only subjects with
   an inner join against entity partitions. Ranking uses the shared edge-rank
   operation and stable identity tie breakers.
   SQL manifests install the display operation before its parsed SQL consumer.
   A native error is propagated; it is not converted into an empty successful read.

F. A failed UI read remains failed until an explicit retry or scope change.
   Entity detail no longer retries whenever its loading flag resets after an
   error. It offers an explicit retry, with loading state also covering that read.
   Home leaderboards use the existing shared read lifecycle and ReadStatus,
   scoped by tenant and signed-in user. A failure remains visible with retry;
   a successful empty result is identified as empty rather than an absent pane.
   API errors retain X-Correlation-Id (legacy X-Request-Id remains a fallback)
   and include it in the displayed error message.

These contracts refine the existing ISA and operation families. They do not
invent a new numeric tier hierarchy or confuse content tier, operation sequence,
and physical implementation layer. The next standardization work should state,
for each operation, its typed inputs, admitted storage/cache planes, required
children/relations, completion disposition, budget, and downstream guarantees.
