# Information-world implementation conformance

The [information-world model](08_PRODUCT_INFORMATION_WORLDS.md) and [corrections ledger](03_CORRECTIONS_LEDGER.md) define the required product. This inventory records implementation boundaries; an available endpoint or a passing browser check does not reduce those requirements.

## Shared context and discovery

| Requirement | Current implementation | Remaining work |
| --- | --- | --- |
| Whole observation and competing interpretations | Monolith combines applicable query reads and canonical entity candidates; modular combines native content, assertions, containment and observed continuations. Results retain separate method measurements. | Explicit interpretation alternatives, obligations and convergent-route evidence across the complete observation. |
| Addressable context and pivots | URL transitions preserve peer coordinates and domain extensions. Monolith selection, classification, comparison, player, game and board-position pivots retain the collection. Modular knowledge, evidence, source, file and research navigation retain originating query and scope. | Complete typed query and transition contracts shared by all service and domain adapters, including interpretation and work state. |
| Unsupported coordinates | Both readers identify retained world, evidence, time or ranking coordinates that their search cannot apply. | Implement those predicates and validate compatibility through discovery. Carrying a URL parameter is not predicate execution. |
| Facet discovery and collection filtering | Checkbox facets compose OR within a field and AND between fields over returned records. Search methods compose rather than requiring a mutually exclusive tool selection. Native schema exposes canonical mask-bank slot IDs and labels from the selected Highway generation. | Discovered values, operators, counts and global predicates for all peer dimensions. Canonical bank enumeration is one part of that contract. |
| Identity and presence | Native discovery matches require database recording or canonical cache presence. Unrecorded calculated roots do not become result rows; known root members and their returned relations remain discoverable, preserving repeated query positions. Explicit direct addressing and geometric calculation retain their distinct status. | Complete cross-adapter discovery semantics and full collection paging under [#1537](https://github.com/SaltyPatron/Laplace/issues/1537). | Search bounds | Monolith exposes supported query dials and band masks, passes their values to query operations and retains them in the address. | Consistent server work envelopes and query contracts across the full collection model. |
| Consistent paging | Monolith entity paging and embedded player-game paging have separate addresses. Modular knowledge and source projections have separate filter and paging keys. | Snapshot-bound cursors, concurrent-write semantics and counts over the complete filtered collection. Current reads are bounded independently. |
| Occurrence identity | Modular ordered-member links carry canonical parent, returned physicality ordinal and logical member ordinal; readback checks the selected member. Equal content at different positions has distinct addresses. | Stable physicality/path anchors and snapshot/version binding. Returned-array ordinals are not a durable occurrence protocol. |

## Evidence boundaries

- `Laplace/web/scripts/test-library-ui.mjs` exercises search composition, execution bounds, URL replay, classification, related structure, comparison and chess pivots with isolated browser fixtures.
- `Laplace-MCP/web/checks/collections.mjs` exercises native-shaped read projections, independent source filters, repeated occurrences, reconstructed file lines and declaration anchors with isolated fixtures.
- Live browser checks exercise installed hosts and actual stored content separately from fixture behavior. They do not establish unimplemented predicates or domain coverage.
- Local builds, deployment receipts, installed-release readback, CI and full invention conformance are separate evidence. Local desktop publication uses the normal owner deployment command; one-time machine provisioning remains separate.

The [search surface audit](12_SEARCH_SURFACE_AUDIT.md) records the reader entrypoints and the remaining contract gaps. Full conformance requires all remaining requirements above and the [product acceptance](../../../Laplace-MCP/web/wwwroot/ACCEPTANCE.md) flows. Bounded repairs must retain that completion boundary.
