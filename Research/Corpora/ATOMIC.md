# ATOMIC

ATOMIC 2020 attests commonsense tuples written as a head, a relation, and a tail, and ATOMIC10X is a model-generated witness of the same shape that enters unrated.

The composition is a tuple: a head, a relation, and a tail. The mask is the relation. The value is the tail asserted of the head. ATOMIC 2020 is the witness ATOMIC 2020 Knowledge Graph, written as three files of those tuples. Root `/vault/Data/Atomic2020`. Loaded measure: 1,913,456 compositions from 68 MB. Deviation 90, the recipe's choice.

ATOMIC10X has the same composition and the same mask. It is not a later edition of the 2020 files. The source file says the tuples were generated by a language model, not written by people, so the witness is ATOMIC10X, it enters unrated at trust 0.67, and it earns trust by agreement with higher-tier witnesses. The recipe reads the refresh file. Loaded measure: 63,925,381 compositions from 1,536 MB. Counting 10X as a second copy of ATOMIC 2020 would treat a generated tuple as the human graph. Counting it as a higher-tier witness would reverse the lineage the recipe records.

Neither file attests a dependency role or a wordnet sense. A tuple that happens to use an English phrase is not a sense attestation. Fanout is the number of tails leaving a head under one relation.

## Files, breakdown, and caveats

Taken from the recipe files. A line in a block is a directive. The prose above it is that file's own account of what is read, what is not, and what a row becomes.

### `atomic-2020/source`

ATOMIC 2020: commonsense tuples, a head, a relation and a tail on every line, in three files. The witness is named as the set's README.md titles itself: "# ATOMIC 2020 Knowledge Graph". The deviation is this recipe's choice for a curated academic resource; the specification does not give one. Measured when it was loaded: 1,913,456 compositions from 68 MB, at 750 bytes each with their indexes and standings.

```text
witness ATOMIC 2020 Knowledge Graph
deviation 90
root $LAPLACE_DATA/Atomic2020
reads text
```

### `atomic-2020/tuples.recipe`

The set's README.md says of its tables:   All data `*.tsv` files are formatted as follows:   - each line represents a distinct commonsense tuple   - column 1: head node/concept   - column 2: edge relation (e.g., xWant,xAttr,AtLocation)   - column 3: tail node/concept The tables have no header row. The three columns are told apart here by the README's words for them; the words only say which column is which, and are never recorded. Every row is recorded in its own order, as written: [head, relation, tail]. A tail written "none" is recorded as written: the README does not say what it stands for.

```text
match train.tsv dev.tsv test.tsv
grammar table
columns head relation tail
claims
subject in head
predicate in relation
object in tail
```

### `atomic-10x/source`

ATOMIC10X: a JSON object on every line, each a head, a relation and a tail, with what the set says of that tuple. The set has no README on this machine. The witness is named as the file names itself: ATOMIC10X.jsonl. What the set says was generated by a language model, not written by people. It enters unrated, at Glicko-2's stock deviation (350, trust 0.67), and earns its trust by its agreement with witnesses of higher tiers (Research: Trust). Measured when it was loaded: 63,925,381 compositions from 1,536 MB, at 750 bytes each with their indexes and standings.

```text
witness ATOMIC10X
trust 0.67
root $LAPLACE_DATA/.refresh-*/Atomic
```

### `atomic-10x/tuples.recipe`

Every line is one object. Its members "head", "relation" and "tail" are the tuple, recorded in that order, each as written: [head, relation, tail]. Its other members ("split", "rec_0.5" .. "rec_0.9", "p_valid_model") are said of the tuple itself, under their own names. "p_valid_model" is a number between 0 and 1 that the set gives every tuple: it is also the score the tuple is attested with.

```text
match ATOMIC10X.jsonl
grammar json
records
claims
subject in head
predicate in relation
object in tail
score in p_valid_model
```
