# ISO 639

ISO 639 attests the identity of a language, which is the value other corpora use when they name a language.

The composition is a language. The mask is identity: which language this code names. The value is the code and the names the standard gives it, from ISO 639-3 (SIL), ISO 639-2 and 639-5 (Library of Congress), and the IANA subtag registry. Witness ISO 639, trust 1.0, read after the Unicode Character Database from `/vault/Data/ISO639`. Loaded measure: 175,147 compositions from 3.7 MB.

Other corpora do not each invent a language code. A treebank directory name, a Wiktextract language field, a Tatoeba language column, and an OpenSubtitles pair all point at this identity. That pointer is a hop from their claim to this one. It is not a second attestation of the language's name. If two corpora spell the same code, they agree by referring here, not by independently naming the language.

ISO 639 does not attest what a sentence in that language means, which sense a word has, or how a token depends on another token. It attests the label those claims use. The archive `iso-639-3_Code_Tables_20260415.zip` beside the tables is the same release.

## Files, breakdown, and caveats

Taken from the recipe files. A line in a block is a directive. The prose above it is that file's own account of what is read, what is not, and what a row becomes.

### `iso-639/cldr-bcp47.recipe`

CLDR's BCP 47 extension data (ldmlBCP47): keys and their types. A key is the thing its name attribute names, and so is a type; every other attribute is said of it under the attribute's own name, and a key says of itself each type written inside it: [key, type, type's name]. "Copyright © 1991-2015 Unicode, Inc." and "CLDR data files are interpreted according to the LDML specification" A type's name stands only within its key: "true" is a type of several keys, and each is a different thing. The thing a type is, then, is the path of its key and its name.

```text
match calendar.xml collation.xml currency.xml measure.xml number.xml segmentation.xml timezone.xml variant.xml transform*.xml bcp47-transform.xml
grammar xml
witness CLDR
identity key name
identity type name within
```

### `iso-639/cldr-likely-subtags.recipe`

CLDR's likely subtags: each likelySubtag element says of what its from attribute names what its other attributes hold, under the attribute's own name. "Copyright © 1991-2026 Unicode, Inc." and "CLDR data files are interpreted according to the LDML specification"

```text
match likelySubtags.xml
grammar xml
witness CLDR
identity likelySubtag from
```

### `iso-639/cldr-supplemental-data.recipe`

CLDR's supplemental data. The elements that name one thing by one attribute are read: each says of that thing what its other attributes hold, under the attribute's own name, and what the elements inside it say (a territory's languagePopulation, a region's currency, a calendar's calendarSystem and era) is said of it, each such element together as one record. "Copyright © 1991-2026 Unicode, Inc." and "CLDR data files are interpreted according to the LDML specification"

```text
match supplementalData.xml
grammar xml
witness CLDR
identity language type
identity territory type
identity group type
identity region iso3166
identity info iso4217
identity territoryCodes type
identity currencyCodes type
identity calendar type
identity scriptVariant id
identity parentLocale parent
identity reference type
```

### `iso-639/cldr-supplemental-metadata.recipe`

CLDR's supplemental metadata: the aliases. Each alias element says of what its type attribute names what its other attributes hold (replacement, reason), under the attribute's own name. "Copyright © 1991-2026 Unicode, Inc." and "CLDR data files are interpreted according to the LDML specification"

```text
match supplementalMetadata.xml
grammar xml
witness CLDR
identity languageAlias type
identity scriptAlias type
identity territoryAlias type
identity subdivisionAlias type

```

### `iso-639/iana.recipe`

The IANA language subtag registry: records of fields. Every field is said of the record's subtag or tag, under the field's own name. The file does not name who publishes it; the directory it is kept in is named iana.

```text
match language-subtag-registry.txt
grammar fields
witness {dir}
```

### `iso-639/iso-639-2.recipe`

The ISO 639-2 list as a table of five fields parted by |, without a header row. The file names none of its fields, and no documentation of them is kept with it, so no field is given a name: each row says its first field and each of its other fields side by side, in the row's own order, [first, other]. The numbers below only say where a field stands in the row; they are not recorded. The file does not name who publishes it; the same list in loc/iso639-2.rdf is the Library of Congress's.

```text
match ISO-639-2_utf-8.txt
grammar table
separator |
columns 1 2 3 4 5
witness Library of Congress
claims
pair
subject in 1
object in 2
claims
pair
subject in 1
object in 3
claims
pair
subject in 1
object in 4
claims
pair
subject in 1
object in 5
```

### `iso-639/iso-639-3.recipe`

ISO 639-3's tables: every row says of its identifier what each column holds, under the column's own name. The tables do not name who publishes them; the pages kept beside them in sil/ are signed "Copyright © 2026 SIL Global".

```text
match iso-639-3.tab iso-639-3_Name_Index.tab iso-639-3_Retirements.tab
grammar table
header
witness SIL Global
claims
subject in Id
attest *
```

### `iso-639/loc-feed.recipe`

The Library of Congress's Atom feed of changes to its ISO 639-5 list. A feed and each entry is the thing its id element names. Of it is said: [id, element, text] for each element inside it that holds text (title, published, updated, subtitle, generator; name and email inside author; p inside content's div); [id, attribute, value] for the attributes of category, content and div; [id, rel, href] for each link, where what it links is not the id itself. A text that carries an attribute says so: [text, attribute, value]. An id that has several entries has all of them said of it; which published goes with which p is not recorded.

```text
match iso639-5.atom10.xml
grammar xml
witness Library of Congress
unit 262144
claims
query
claims
distinct
query
```

### `iso-639/loc.recipe`

The Library of Congress's lists of ISO 639-1, 639-2 and 639-5 in RDF/XML, the fullest of the four formats it publishes them in. Every statement is recorded as written: the subject is what rdf:about names, the predicate the property element's own name, the object its text, or what its rdf:resource names, or what the rdf:about of the element inside it names. An element that carries rdf:about says its own name of what it names: [subject, name], the file writes nothing between the two. A text that carries an attribute says so: [text, attribute, value]. rdf:about is the first attribute wherever these files write it; the patterns name it by position.

```text
match iso639-?.rdf
grammar xml
witness Library of Congress
unit 1048576
claims
query
claims
pair
query
```
